# 04 — Commands, queries, transactions, and errors

Read [Data model](03-data-model.md) before implementing this boundary. Every screen uses these application contracts; widgets must not write persistence directly. Names below are conceptual API names, not required language syntax.

## Envelope and consistency

Commands carry `requestId`, contract version, payload, and affected entity versions or expected library/group revision. Success returns committed revision and affected IDs. A request ID deduplicates retries of the same payload; reusing it for different content is an error. Domain writes, history, order changes, and revision increments commit in one transaction. Emit invalidation events only after commit; a crash before emission is recovered by comparing revision on reconnect.

Use optimistic concurrency for editor fields and ranking operations. A stale command returns `Conflict` with latest values and does not overwrite another tab. The UI can offer reload or an explicit retry against the current state. Automatically retry reads, not semantically changed writes. A refresh must not overwrite an unsaved text draft.

Undo is a compensating command, not deletion of audit history. Offer a visible undo toast for ordinary rating/order/tag/type edits. It succeeds only if touched records still match the post-command versions; otherwise explain the conflict and offer ordinary editing. Duel retraction keeps the original answer and records its removal. Purge is not undoable.

Every manual order, direct duel answer, skip, retraction, and reconciliation is committed with the relevant history and revision state. For each tier persist latest ranking-input sequence E, last successfully fitted sequence C, and durable `pendingReconcile`. Direct judgments and retractions advance E and set the flag true; skips do neither. Manual order or membership changes advance E, set the flag false (superseding any pending automatic reorder), and queue a fit without reconciliation. C < E means the posterior cache is dirty and requires a fit; C = E is fit-clean; reject C > E. Startup/import queues a fit whenever C < E and queues reconciliation whenever pendingReconcile is true, even if C = E. The fit worker captures E, membership, and model version; it advances C only if those inputs remain current and does not change GroupOrder or clear the flag. The reconciliation worker uses that fit and captures E, membership, model version, order revision, and the flag; it writes swaps and clears the flag only if those inputs still match and the flag is true. A manual/membership edit during either job clears the flag and changes the order revision, so a stale automatic result cannot undo the edit. If the posterior cache is absent after restart/import, rebuild it deterministically from durable evidence before reconciliation even when C = E. The model posterior is a disposable cache; persisted GroupOrder rows are canonical truth. A fit uses all active entries and evidence in its current score tier, even when the session filter selects a subset for pair presentation. No alternate filtered model is allowed. Import commits archived canonical order and state first; failed/stale jobs leave that order intact.

Every presented pair records which work appeared on the left and right, including skips. Choose the orientation that minimizes the two works' total squared left/right presentation imbalance using persisted per-work side counts; break an exact tie with the session seed. Orientation is part of the response event and remains fixed for replay. A skipped presentation counts for side balance but not evidence, graph coverage, or the 20-answer pair cooldown.

SetOverallRating, SetDisposition, TrashEntry, RestoreEntry, and MoveEntry can alter tier membership. Membership changes retain direct duel history but exclude pairs from a tier fit while either work is outside that tier; the judgments become eligible again if both return to the same tier. Refit each affected tier from all of its current entries/evidence. A manual order or membership change commits its exact placement first, clears any pending automatic-reconciliation intent, and never triggers reconciliation by itself; it marks the fit dirty for future duel selection. Pair exploitation waits for that fit, while disconnected-graph coverage may use the deterministic saved-seed fallback. A later accepted direct answer or retraction sets pendingReconcile and may reconcile the full tier; a manual edit that happens first supersedes that pending reorder.

## Query inventory and payloads

- `GetLibrarySlice(group, filter, viewSort, cursor, limit)`: stable IDs, display fields, `rankingPlaced`, nullable full and filtered rank, placed/unplaced counts, and revision; default canonical placed order with a separate unplaced tray. Cursor bound to filter/sort/revision and reset when stale.
- `GetRankingView(revision)`: all 10 score tiers with ordered placed IDs, stable unplaced-tray IDs, placed/unplaced counts, pending fit/reconciliation status, current ordinary or placement-assist session, and shared revision.
- `SearchEntries(query, scope, cursor)`: title/short label primary, optional review/tag search toggles; include groupId and sufficient disambiguation; hide trash. A short label replaces an overflowing full title only in constrained media cards; details and accessibility retain the full title.
- `GetEntryDetails(id)`: current entry, active and retained criteria, rank projections, history, relevant statistics and provenance.
- `GetGroupSummary(filter)`: all ordered groups and counts, preserving empty groups.
- `GetSceneProjection(group, filter)`: stable object ID, full-group placement index, title/short label, palette, visible flag, selection; avoid transferring full reviews or decoded images.
- `GetAnalytics(filter, revision)`: aggregates plus eligible insight descriptors, thresholds, denominators, excluded-field counts and algorithm version.
- `GetRecapEligibility(filter)`: templates, available styles/modes, counts, missing-field reasons.
- `GetHomeProfile`: explicit inputs, derived radar values with sample counts, guidelines.
- `GetWorkspace`, `GetSettings`, `GetDuelState`, `GetJobStatus`: versioned DTOs.

Filter contract: optional type IDs including explicit “No type”, tag IDs with any/all mode, disposition, inclusive release-year bounds, cover presence, criterion completeness, and text. There is no overall-score filter; score groups remain directly navigable. AND across categories; selected values within one type category use OR. Missing years do not match a year range; expose excluded count. Empty selected sets mean no restriction. Serialize normalized filters for tabs, sessions, and compositions.

Alternate table sorts are presentation only; disable drag reordering until returning to canonical order. Query limits are bounded (default 100, max 500); virtualized lists fetch more. Analytics jobs use a consistent snapshot. Cache keys include revision, filter, locale where relevant, and algorithm version. Session participant selection is capped at 200, but this is not a group or fit limit; large-tier sparse solves run as background work and must not omit entries or fabricate confidence if they fail.

## Failure model

Typed errors: Validation, NotFound, Conflict, NeedsConfirmation, UnsupportedVersion, PermissionDenied, DiskFull, AssetUnavailable, Cancelled, Internal. Map stable error codes to contextual localized messages with actionable recovery; do not expose untranslated fixed English from the storage layer. Preserve drafts on failed writes; never display “Saved” before commit. Technical diagnostics omit review text and user file paths by default.

Background jobs report queued/running/progress/completed/failed/cancelled plus results. Cancellation is safe before commit; once atomic commit starts, finish it and report completion. Export cancellation removes temporary output. Busy jobs must not block tab navigation. If a duel fit fails or returns a nonpositive/nonfinite contrast variance, retain the answer and current canonical order, report a retryable fit state, and do not apply a partial reorder.

## Acceptance

Two tabs moving the same work cannot silently undo each other. Confirming deletion after a new affected entry was added requires a fresh impact preview. Crashing between a write and invalidation still yields consistent queries after restart. Repeated command submission with the same request ID creates one event, not two.
