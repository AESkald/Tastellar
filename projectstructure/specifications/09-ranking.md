# 09 — Canonical ranking, manual ordering, and duels

## One canonical order

There is one persisted order for the placed works in each rating tier. The same order drives Ranking, Library, entry details, [Analytics](10-analytics.md), Home evidence, and Recap. Rated but unplaced works appear in a separate Unplaced tray for their score tier and have no ordinal rank until the user confirms a position. There is no duel-only ranking, proposal, or Apply step. An accepted ordinary duel answer becomes durable evidence, then a background fit may make confidence-qualified local changes to that same canonical order. A manual move changes the canonical order immediately.

The global placed order is the concatenation of fixed score tiers 10 through 1; each tier's Unplaced tray follows its placed list. Duels operate inside one tier and never change an overall score, disposition, or tier. Media type is a filter only; works of different types can be compared inside the same score tier. Moving an entry between score tiers remains an explicit manual score change. Planned, Dropped, and Unrated groups keep their own canonical display order and are not duel-ranked.

## Bayesian pairwise model

Each work i in a rating tier has a latent preference value θᵢ. Values are relative within that tier; they do not replace the user's 1–10 overall score. Let πᵢ = exp(θᵢ). Version 1 uses the Davidson categorical likelihood for a direct comparison of i and j:

$$
Z_{ij}=π_i+π_j+ν\sqrt{π_iπ_j},\qquad ν=0.5
$$

$$
P(i\text{ wins})=π_i/Z_{ij},\quad
P(j\text{ wins})=π_j/Z_{ij},\quad
P(\text{tie})=ν\sqrt{π_iπ_j}/Z_{ij}.
$$

At equal θ, this fixed initial tie parameter gives a 20% tie probability. The value is a versioned tuning default, not a claim about every user's tie rate. “I can't choose” records a tie. Skip records no preference likelihood.

All direct win, loss, and tie judgments remain in the durable history and contribute one unit of log-likelihood each. Repeated judgments therefore add evidence. The ordinary scheduler normally waits until at least 20 other answered comparisons in that tier before repeating a pair; explicit Revisit can ask sooner. If no fresh eligible pair remains, it may revisit a cooling-down pair automatically so a two-work tier never appears caught up while a comparison remains possible. To correct a mistaken answer, the user retracts that specific judgment. Retraction is itself recorded, and the original answer remains in audit history but no longer contributes to the fit. Skip records do not count as answered comparisons for the cooldown.

The prior is θ ∼ N(0, I) on the zero-sum subspace Σᵢθᵢ=0. The fit is the posterior mode of all non-retracted direct judgments and active manual boundary factors:

$$
L(θ)=-\sum_{r\in D}\log P(y_r\mid θ)
-\sum_{m\in M} w_m\log σ(q_m(θ_a-θ_b))
+\frac12\sum_i θ_i^2,
\qquad σ(x)=\frac1{1+e^{-x}}.
$$

Here D contains one term per direct judgment, including repeats; y is left win, right win, or tie. Each m is a soft binary preference boundary added by a manual move; q is +1 or −1 according to its stated direction. The fitted scores are centered, and the inverse Hessian at the mode gives the Laplace covariance Σ. The posterior and covariance are model estimates, not certainty guarantees.

Use stable log-sum-exp evaluation and a deterministic damped Newton solver with a positive-definite prior-regularized Hessian and backtracking line search. Fix variable order by stable entry ID for solver work, independent of display order. Stop when the maximum parameter change is below 0.000001 or after 200 iterations. Any numerical or convergence failure keeps the already saved answer, leaves the order as-is, and offers a retry. Never discard evidence because a fit failed.

Cycles are valid observations. The model returns finite scores and uncertainty for cyclic outcomes; it does not erase an edge or assume every matchup has one context-free answer. Ties can leave a pair close without forcing equal display ranks. Manual order is not fabricated as a duel win.

## Manual moves and bounded ordinal evidence

Within a group, a drag inserts the moved entry immediately before the target in the full group. Dropping after the last visible card inserts immediately after that visible card. Hidden entries keep their relative order, but may shift around the moved entry as required by the insertion. Show that the full ranking changes. Keyboard Move up/down/to position/to group uses the same domain command.

The requested move commits to the canonical order before any model fitting; never let the model immediately undo a manual action. Persist its boundary-factor changes, advance the affected tier's model-input sequence, set its durable `pendingReconcile` flag false, and promptly refit the posterior without running order reconciliation. This manual event supersedes any pending automatic reorder, so a duel fit already in flight must fail its order-revision guard. A later duel answer or retraction is required before an automatic order change can follow the manual move. If pair selection runs before the refit completes, wait for that fit; if the comparison graph is disconnected, it may show a deterministic coverage edge chosen from the saved session seed and comparison counts. Do not use a stale posterior to exploit or prioritize pairs. A same-tier filtered drag uses the exact visible-target insertion rule above. For a filtered cross-tier drag, resolve a visible destination target against the full destination tier using the same before/after semantics as a within-tier drag; entries hidden by the filter remain in their relative positions, and the moved entry is inserted immediately before or after the anchored entry in the full tier. If the destination has no visible target (including an empty visible result), the command must explicitly choose start or end of the full destination tier; reject ambiguous drops. An unfiltered cross-tier move changes score and order in one transaction. Moving to Unrated clears the score and keeps disposition Experienced; moving to Planned or Dropped clears the score and sets that disposition, with visible wording and undo.

A manual move adds at most two local soft preference factors: left neighbor > moved entry, and moved entry > right neighbor. It adds no factor at a missing group edge. The total evidence mass for one move is κ=1, divided equally among the available boundaries (one boundary has weight 1; two have weight 0.5 each). Each factor is a binary logistic likelihood σ(θ_higher−θ_lower)^w. It does not create one artificial judgment for every crossed work and does not encode an artificial midpoint score.

There is at most one active manual factor for a given unordered pair in a tier. A later manual placement involving that pair supersedes the previous factor; retain both events in history. An active manual boundary is protected from automatic reversal until a later direct duel of that exact unordered pair produces a win opposite to the boundary. An agreeing win, tie, or skip does not unlock it. The boundary factor remains part of the model after unlock, so later direct evidence must outweigh rather than erase the manual intent. A later manual edit of either endpoint supersedes its old boundary factors; also retire any active factor contradicted by the new exact order. Any rating-tier membership change retires manual factors involving the moved entry. Record every addition and retirement for replay.

## Fit freshness and reorder intent

Persist per-tier state `(E, C, pendingReconcile)`. E is the monotonically increasing ranking-input sequence; increment it for each direct judgment, duel retraction, manual placement/factor change, and tier-membership change. C is the latest E for which a fit completed successfully. `C < E` means the posterior cache is dirty and needs a refit; `C = E` means the fit is current; `C > E` is invalid. `pendingReconcile` is a separate durable boolean, not derivable from E and C: it means accepted duel evidence or a retraction still requests an automatic order pass after a successful fit.

A direct win/loss/tie and a direct judgment retraction set `pendingReconcile=true`. Skip changes neither E nor the flag. Any manual insertion or tier-membership change sets the flag false, superseding pending automatic reorder intent so the exact manual placement remains authoritative; those edits still advance E because the placement/factor or membership changed. A subsequent direct answer/retraction may set the flag true again. A fit job advances C to its captured E if E, membership, and model version still match; it never changes GroupOrder. A separate reconciliation job uses that fit only if the durable flag remains true and E, membership, model version, and captured order revision still match; commit swaps, OrderEvents, revision, and clearing the flag atomically. If manual editing races with a duel job, the edit clears the flag and changes order revision, invalidating its automatic result. Recovery schedules work whenever `C < E` or `pendingReconcile=true`: refit dirty inputs, rebuild the disposable posterior if absent, and reconcile only when the durable flag asks for it. Thus a clean fit may still need a pending reconciliation, and a dirty manual-only fit must never reorder.

## Continuous, confidence-qualified reconciliation

After each accepted ordinary win, loss, or tie, persist the answer, advance E, set `pendingReconcile=true`, fit the affected tier off the interactive thread, and reconcile the full placed list if the flag and captured revisions remain current. A retraction also advances E and requests reconciliation; skip changes no preference likelihood and triggers no fit. Ordinary sessions compare placed works only. A filter only chooses which placed pairs are shown; reconciliation considers the full placed list, including hidden works. Unplaced works stay in their tray until manually or binary placed; ordinary reconciliation never inserts them. A hidden placed work can move only through an adjacent swap that independently satisfies the same confidence rule and is not protected by a manual boundary.

For adjacent works A before B in the current order, let B be the lower work and define:

$$
d=μ_B-μ_A,\qquad
v=Σ_{BB}+Σ_{AA}-2Σ_{AB}.
$$

Swap the adjacent pair only when all of these hold:

1. d > δ, where δ = log(1.5) ≈ 0.405 logits. This initial practical margin means conditional win-to-loss odds of at least 1.5-to-1 under Bradley–Terry (conditioning on a decisive, non-tie outcome).
2. Φ((d−δ)/√v) ≥ q, with q = 0.90 under the Laplace approximation.
3. The pair is not a protected manual boundary.

These are initial, versioned tuning defaults. They express “enough evidence to move” and do not state a 90% probability that the whole ranking is correct. If v is nonpositive or nonfinite, or the CDF calculation fails, do not swap; keep the current order and report a retryable fit failure.

Reconciliation starts at the top of the current placed list. Scan adjacent placed pairs in order; when a swap qualifies, commit it in the in-memory candidate sequence and restart from the top. Stop after a complete pass with no eligible swap. At fixed fitted μ, each swap increases the weighted order utility Σᵣ(n−r)μᵣ, so the process terminates after finitely many swaps even with cycles in the observed judgments. Stable current order resolves every pair that does not pass the threshold. Record the changed IDs and old/new neighbors as OrderEvents.

Each answer is durable before fitting. Apply a completed fit only if its input E, group membership fingerprint, and algorithm version still match; otherwise discard it and fit again from current state. The fit checkpoint C=E can commit independently from order reconciliation, leaving `pendingReconcile=true` for recovery if the process stops between stages. Reconciliation uses a fit for current E and applies only if E, membership, algorithm version, captured canonical-order revision, and the still-true flag match. Commit swaps, OrderEvents, order revision, and clearing the flag atomically. A fit with the flag false updates no order. The UI reports moved works concisely. The latest canonical order, never the model cache, is the value read by Library and Analytics.

## Pair selection and sessions

A normal duel session uses one rating tier and a normalized optional filter, with 2–200 placed participants. The filter selects possible duel candidates, not a separate ranking. Above 200 eligible normal-duel candidates, ask for a filter or explicit subset; never silently sample and label it a whole-tier ranking. Binary placement remains available regardless of the number of placed works. If confirming a binary placement would leave more than 200 normal-duel participants under the current filter, ask the user to choose a filter or explicit subset before continuing with normal duels. This cap limits session candidates only: fit one posterior from all active entries and evidence in the current tier, and reconcile the full tier. Do not create a second model per filter. Use a sparse Hessian assembled from observed pair factors and prior diagonals, and deterministic sparse linear solves for the Newton step and required pair-contrast variances. Benchmark large tiers. If a solve fails its tolerance or exceeds its safe computation budget, retain the answer and current order, show the pending fit state, and retry; never silently exclude works or fabricate confidence. One eligible work gets an explanatory empty state.

Persist the session ID, tier, filter snapshot, exact participant IDs, whether they are an explicit normal-duel subset, membership fingerprint, scheduler/algorithm version, seed, event sequence, and pause/completion state. Sessions resume offline. Active pair evidence persists across sessions for every pair currently in the same tier; moving a work to another tier retains old evidence but excludes it from that tier's fit while separated.

1. Build the comparison graph from non-retracted direct duel judgments among the placed session participants. Manual factors do not count as user-comparison coverage. If disconnected, use a seeded shuffle and offer edges bridging distinct components, prioritizing the least-compared endpoints. Previously collected evidence can satisfy coverage across sessions.
2. A Skip is durable but adds no graph edge. Defer that pair for the current coverage block and offer a replacement that improves graph coverage when possible.
3. Once connected, choose among unseen or cooldown-eligible pairs. For each candidate pair i,j, let d=μᵢ−μⱼ, v=Var(θᵢ−θⱼ), and Pᵢ, Pⱼ, Ptie be its Davidson probabilities at d. Its scalar Fisher information is J(d)=((Pᵢ+Pⱼ)−(Pᵢ−Pⱼ)²)/4; approximate information gain by IGᵢⱼ=0.5 log(1+vJ(d)). Let cᵢ be the number of answered direct comparisons involving i, nᵢⱼ the non-retracted direct comparison count for the pair, and rᵢ its current 1-based rank among placed works in the tier. With n session participants, set h=max(5,ceil(n/20)), rankFactor=exp(−|rᵢ−rⱼ|/h), coverageFactor=1+0.5/(1+cᵢ)+0.5/(1+cⱼ), and repeatFactor=1/sqrt(1+nᵢⱼ). Define conflictFactor=1+2I[the pair is a protected manual boundary whose posterior mean favors the opposite direction]+I[current order opposes the model with posterior probability greater than 0.65], where I[condition] is 1 when true and 0 otherwise. Outside exploration, maximize Aᵢⱼ=IGᵢⱼ × rankFactor × coverageFactor × conflictFactor × repeatFactor. Every fifth answered comparison explores the least-compared works: among eligible pairs containing a least-compared participant, choose the pair with the highest IG. Coverage edges between disconnected graph components take priority; choose the edge maximizing coverageFactor, then Aᵢⱼ. Cooldown makes a pair ineligible unless explicitly revisited. A stored session seed and stable IDs break remaining ties.
   When the placed order opposes the posterior on an adjacent pair, multiply its utility by a local-correction bonus of 10 so direct order conflicts can be resolved promptly.
4. Do not repeat a pair before its 20-other-answer cooldown while any fresh eligible pair remains, unless the user chooses Revisit. If all eligible pairs are cooling down, automatically relax cooldown for the next prompt; skipped pairs remain excluded from the current session. If every pair is skipped, end the session. A direct repeated answer is a new unit of evidence; an explicit retraction corrects an accidental or mistaken answer.
5. Fit after a direct answer or retraction; reconcile only while `pendingReconcile=true` and the captured revisions still match. A decisive normal answer that puts a currently lower winner below its loser immediately moves that winner before the loser if this move crosses no other protected manual boundary. Record that bounded correction as an OrderEvent, then run posterior reconciliation. A direct opposing answer unlocks its own protected manual boundary through judgment provenance; other protected boundaries remain in force. Ties do not move the order. Membership and manual-order changes mark affected tier fits dirty, clear the flag, and refit without reconciliation; they never cause unrelated order changes by themselves. Starting another session ends the prior active session. A stale prompt or frozen snapshot ends and replaces its session automatically; the old answer is discarded. Pause, resume, and end are available at any time. Ending a session does not undo its answers or its order changes; there is no proposal or separate application step.

Before presenting a selected unordered pair, choose left/right orientation by minimizing the sum of the two works' squared side imbalances after that presentation: for works i,j compare (Lᵢ'−Rᵢ')²+(Lⱼ'−Rⱼ')² for both orientations. L and R count all prior presentations, including skips and retracted answers. Choose the lower-imbalance orientation; break an exact tie with the stored session seed. Persist the presented sides for every answer or skip so replay reproduces the screen and can audit position balance.

Show answered comparisons, works seen, connected-graph coverage, skips, and recent order changes. Do not make unsupported “95% accurate” claims. Explain that some preferences depend on the matchup when cycles occur. Do not describe the user as inconsistent.

## Unplaced works and binary placement assist

Each active rated work is either `placed` or `unplaced`; this state is separate from its 1–10 overall rating. A newly rated work starts unplaced. Existing rated works migrate as placed in their existing order. Unplaced works stay visible in a separate tier tray and have no ordinal rank. Ordinary duels choose pairs only from placed works; ordinary model fits still include all active tier entries and all active same-tier evidence, including binary-assist answers involving unplaced works. Confidence-qualified reconciliation can swap placed entries only and never places an unplaced work implicitly.

For each tier t, compute the placed share from active rated works:

$$
s_t=\frac{P_t}{P_t+U_t},
$$

where Pₜ and Uₜ are the placed and unplaced counts. If the denominator is zero, treat the share as zero. When `sₜ ≥ 0.90` and Uₜ > 0, suggest binary placement for a newly rated work and prioritize available unplaced works when the user enters Duels. Once the unplaced queue is cleared, continue with ordinary duels. With zero placed and at least two unplaced works, the first duel is a seed comparison between two unplaced works; a decisive answer places both in winner-first order, a tie places them in their prior stable order, and Skip tries another unskipped pair. If there is exactly one work total, it may be placed directly. With one placed work and unplaced work remaining, use binary insertion. With two or more placed works, run ordinary duels; the user can still start binary insertion for any selected unplaced work. When `sₜ < 0.90`, ordinary duels remain available while the unplaced tray stays accessible. Manual placement by dragging from the Unplaced tray is always available.

The 90% placed-share trigger is a **count threshold**, not a confidence probability. It is independent of q=0.90 in the automatic adjacent-swap rule above, which is a Laplace-approximated pairwise posterior confidence threshold. Do not present either 90% value as a guarantee that a whole tier is correctly ordered.

Binary insertion selects one scored unplaced target and freezes the current ordered IDs of the placed works in its tier, plus membership and order revisions. Finish or clear any prior pending reconciliation before taking the snapshot. If N works are in that snapshot, initialize the half-open pivot-index interval `[lo,hi)=[0,N)`. While `lo < hi`, let `mid=floor((lo+hi)/2)` and compare the target with the frozen work at `mid`:

- If the target wins, set `hi=mid` (the insertion lies before that pivot).
- If the pivot wins, set `lo=mid+1` (the insertion lies after that pivot).
- If they tie, record the Davidson tie and stop with the proposed gap immediately after the pivot, at `mid+1`.
- If the user skips, persist the skip and defer the target without placing it.

For non-tie answers, when `lo=hi`, that value is the proposed gap in `0…N`; the N+1 possible gaps include the beginning and end. Show the exact proposed insertion and require confirmation. A stale membership/order revision invalidates the snapshot; end and restart the session against current state rather than placing against an obsolete list. Starting a new session also ends the previous active session.

Every accepted binary choice is a direct, unit-weight preference judgment for the target/pivot pair and remains in durable history. During an active placement assist, these answers advance E but keep `pendingReconcile=false`; ordinary reconciliation is suspended so the frozen pivots and display order do not move. A tie also ends the search and awaits position confirmation. On confirmation, insert the target exactly at the selected gap, mark it placed, record the usual bounded local manual factors and OrderEvent, keep reconciliation false, and refit the tier without global swaps. The user may adjust the confirmed position manually afterward. On abort, retain any completed judgments but leave the target unplaced and do not reconcile. A future ordinary duel can set `pendingReconcile=true` and allow the standard placed-only adjacent pass.

## Undo, replay, and persistence

Every manual insertion, rating-tier change, duel response, retraction, automatic adjacent swap, and constraint retirement has an append-only event with an algorithm version and committed revision. The current GroupOrder rows are the canonical state. The fitted posterior is disposable and rebuildable from direct responses plus active manual factors. Replaying an event log with the same algorithm version and stored session seeds produces the same pair schedule and reconciliation decisions; persisted OrderEvents preserve the exact canonical result across upgrades and platforms.

Undo is a compensating command guarded by expected tier/order revisions. It restores exact prior order only when no later order operation has superseded the affected interval. Undoing a manual order is itself a manual placement and clears pending automatic reconciliation. Retracting a duel answer preserves its audit record and removes its likelihood contribution. Retracting a win/loss/tie advances E, updates only the active boundary-unlock evidence associated with that judgment, sets `pendingReconcile=true`, and starts a guarded refit/reconciliation; retracting a skip is history-only and leaves E unchanged. A boundary unlock is attributed only to a direct opposing win recorded after that boundary was created. Retracting one such win leaves the boundary unlocked while another attributed opposing win remains; retracting the last removes the unlock evidence and restores the lock. Retraction does not directly rewrite canonical order to restore an old preferred position: any resulting order change must pass the current guarded reconciliation rules, preserving later manual edits. A stale command does not overwrite newer manual or duel changes. Every resulting order and history write is atomic. On startup, schedule work whenever C<E or `pendingReconcile=true`, then follow the flag: manual-only dirtiness refits the model but cannot reorder; a pending direct-evidence update may reconcile after guarded fitting. Thus a crash after saving an answer but before applying its reorder cannot lose the answer or falsely mark the tier current. A failed or stale job leaves canonical order and pending intent intact until a valid job completes.

Use one documented variable-length lexicographic order-key algorithm with SQLite BINARY collation. Generate a key between full-group neighbors in the Rust domain core. Never use floating-point rank storage or locale collation. A single writer detects collisions and retries in the transaction; rebalance a group atomically when no key fits or a key exceeds 64 bytes, preserving exact ID order. Typical automatic swaps update the affected neighboring keys only. Persist the key-algorithm version; keys are opaque in UI and portable data.

Portable archive v2 preserves placed/unplaced status, canonical order keys, `orderKeyAlgorithmVersion`, ordinary and placement-assist sessions and snapshots, explicit-subset flags, all direct response/retraction history, manual boundary factors and their unlock-judgment references, each tier's E, C, `pendingReconcile`, and OrderEvents. Its nested ranking payload is schema version 3, with explicit input sequences on judgments and creation sequences on boundaries. Nested ranking schema versions 1 and 2 lack this chronology: import preserves an old unlocked state with a legacy marker, clears unproven unlock links, and does not fabricate provenance. Schema version 3 requires each unlock judgment to be active, opposing, for the same pair and tier, and later than the boundary's creation sequence. Active binary snapshots, candidates, bounds, and presented pivots must match the restored tier before import succeeds. A checkpoint may be older than E: that is valid dirty input; C may not exceed E. Import preserves placement state, canonical sequence, and `(E,C,pendingReconcile)` atomically and does not reconcile inside the import transaction. After successful commit/startup, queue work for C<E or `pendingReconcile=true`; fit dirty inputs, but reconcile only when the preserved flag is true and revision guards pass. A fit-only recovery must leave the archived placed order unchanged. Version 1 archives have no key-version field, so treat their keys as algorithm 1, sort under that rule, and re-encode under current algorithm 2 while preserving each group's exact entry sequence. They mark rated works placed and start with no fabricated duel evidence. A version 2 archive that declares a recognized older key algorithm is handled the same way; current-version keys are preserved. SQLite migrations mark current rated entries placed without changing score tiers or relative order, and produce pre-migration backups.

## Cross-media guidance and acceptance

Guidance says users may compare different media by plot, world, characters, craft, or overall enjoyment; objectivity is not required. Keep this help available in Duels and general Help. If the user has read the dedicated guidance, hide its extra shortcut from Tier list; store that preference separately from whether mode help was read.

Acceptance fixtures cover ties, skip, cycles, repeated evidence, explicit retraction, a manual boundary that remains locked through skip/tie/agreement and unlocks only on an opposing win, filtered sessions that reconcile the full placed list, stale background fits, deterministic replay, and crash recovery after answer persistence. Interleaving fixtures must prove: manual/membership edits set `pendingReconcile=false` and preserve exact order even when a duel fit was already queued; C<E with flag false refits without swaps; C=E with flag true still schedules guarded reconciliation; duel evidence sets the flag true; and startup/import dispatch follows the persisted flag. Placement fixtures prove the ≥90% placed-share suggestion is a count threshold independent of q=0.90, boundary cases for N=0/1 and intervals at both ends, new-win/pivot-win interval narrowing, tie-after-pivot proposal, Skip/abort retention, frozen-order invalidation, no reorder while assisting, and exact confirmation with later ordinary reconciliation. Reset fixtures prove all scored entries become unplaced while entries, overall scores, unscored order, and backups/exports remain unchanged; stale revisions do not reset; version 1 archives migrate rated entries as placed. Manual insertion fixtures cover visible targets with hidden entries, group edges, repeated gap insertion, and rebalance. Library, Ranking, Analytics, Home evidence, and Recap must return the same placed order for one revision.
