# 20 — Analytics foundation

Analytics is a scrollable feed over the active library, using the same ranked snapshot as Library and Ranking. All interface copy is keyed in `en.json` through the shared localization helper. The page remains empty below 20 active rated works and links to the Library to add more ratings; it does not partially show metrics or small top lists.

The five-section feed starts with a 1–10 rating histogram. It shows only scores with rated works, and each shown bin includes its count and percentage of all rated works alongside summary statistics and deterministic, tentative shape observations; rarity is part of the histogram rather than a separate section. Its count axis uses rounded ticks and headroom so the tallest count label stays above its bar. The media chart uses each saved media type's display name, including the built-in “Animation” type, shows only scores represented by a plotted type, includes ordered pair-by-pair comparisons and calls out the highest supported share of 8–10 ratings. Tags such as “Anime” remain separate labels. A ranked line chart follows: its 0–1 vertical scale compares average within-tier positions across media types, with included weights summing to one within each score. It reads only validated placed work order, reports coverage under each rated score, and leaves unavailable tiers as gaps. A sparse-but-placed type can have a zero point when excluded by the support rule; an unplaced-only type has no point. The legend lists only types with plotted points. Clicking a plotted type opens the same whole-tier table for that score, regardless of the clicked type; the method explanation appears under the chart. Light mode uses the dark analytics palette, while reading mode keeps distinct series colors and uses a sage-to-teal gradient for the first histogram. Histogram and media marks open contributor inspection; ranked points open the tier table. Inspection modals retain balanced horizontal padding.

The top-list section offers one eligible ranked slice. Candidates use media types and established tags, require at least eight placed eligible works plus ranking spread, and preserve a tag candidate even when it contains the same works as its media type. A per-view shuffle picks a new filter; refresh avoids the previous filter when alternatives exist, including a different label over the same set of works. Date-dependent filters remain omitted from this implementation. The last section reviews an adjacent score boundary and supports confirming or moving works.

The boundary review compares the lowest placed work in one tier with the highest placed work in the adjacent tier. Users can keep the pair, move either work across the boundary, edit a work, or reset completed reviews. Confirmed pair fingerprints are stored in the existing preferences object and round-trip through portable archive export/import. Moves use the normal ranking operation, so the Library, Ranking and Analytics views update together.

## Validation

Analytics domain tests cover sparse thresholds, malformed ranking references, rating distributions, media comparisons, normalized tier scores, partial coverage, top-list selection, and boundary-review fingerprints. Archive tests verify review preferences survive export/import and default correctly in older preferences.

Browser tests use an isolated preview seeded with the supplied save (247 rated works) and synthetic fixtures. They cover the 20-work visibility threshold, histogram and chart behavior, partial or unplaced ranking data, filters, boundary actions, theme palettes, and narrow layouts. Preview data stays in browser session storage and is not imported into the native library.

Validation on 2026-10-03: the production build passed, as did 36 Analytics domain tests and 3 browser tests. The full frontend suite reported 70/72, with two existing `sceneLayout.test.ts` failures for constellation viewport sizing and deep-field brightness. Earlier checks passed 8/8 domain tests and 1/1 portable-archive round-trip. Visual review covered dark, light, and reading themes at wide and 390px layouts. At that time, Windows and Android builds, packaged release behavior, native-webview performance, and broader accessibility remained unverified.
