# Steam import and metadata-enrichment notes

Reviewed 2026-10-03. Primary-source research for design only; no Steam API request was made and no account credentials or private profile data were accessed. Confidence is high where a current first-party specification is cited; gaps are marked explicitly. This is not legal advice.

## Steam: what an official user-list import can and cannot do

| User asks about | Officially documented capability | Import meaning / limits |
|---|---|---|
| Games the account owns | [`IPlayerService/GetOwnedGames`](https://partner.steamgames.com/doc/webapi/IPlayerService?l=english&language=english) takes an API key and SteamID; returns the game list if the user's owned games and details are visible. `include_appinfo` adds name/icon. Free games are excluded by default; `include_played_free_games=true` returns free games the user has played. | Store `appid` as the external identity and map rows to `games`; this is a Steam library/ownership import. It does not mean installed, started, completed, or personally rated. The spec does not clearly establish whether every DLC-only entitlement is returned; do not promise DLC completeness without a fixture/API response. |
| Recently played / playtime | The same interface documents [`GetRecentlyPlayedGames`](https://partner.steamgames.com/doc/webapi/IPlayerService?l=english&language=english) and [`GetSingleGamePlaytime`](https://partner.steamgames.com/doc/webapi/IPlayerService?l=english&language=english), keyed by SteamID and game AppID. | Map only to recent activity/playtime fields. Recently played means recently launched, not a completion signal. Steam playtime is not Tastellar's rating or completion state. |
| Achievements / game stats | [`ISteamUserStats`](https://partner.steamgames.com/doc/webapi/ISteamUserStats?l=english) documents per-game achievements and stats APIs. The user-achievement methods are scoped to a particular game/AppID; achievement definitions are set by the game. | Optional future enrichment, not a reliable universal completion metric: games may have no achievements, may define arbitrary achievements, and completion criteria differ. Do not infer completed from achievement count/percentage. |
| Wishlist | Steam Support says wishlist visibility follows profile privacy and can be shown to everyone, friends, or only the account ([Wishlist FAQ](https://help.steampowered.com/en/faqs/view/0CAD-3B4D-B874-A065)). Valve's 2026 announcement for a “Wishlist Data API” describes “Programmatic access to your game's wishlisting data” ([Steamworks announcement](https://steamcommunity.com/gid/103582791433666425/announcements/detail/499474120884358024)). | That announcement is developer-facing data about wishlisting of a developer's own game; it does not document a user's personal wishlist-read endpoint. No first-party spec establishing a consumer API for importing an end-user's wishlist was found. Keep user wishlist import out until Valve documents/authorizes that exact use. Do not rely on undocumented Store/Community JSON routes. |
| Store cart | The official [ItemCart documentation](https://partner.steamgames.com/doc/features/inventory/webfunctions) is a developer checkout flow: a game/store builds and maintains its cart, then POSTs it to Steam to purchase in-game inventory items. | This is not an API to read the signed-in user's Steam store cart. No official consumer cart-read API was found. Do not use internal/undocumented Store endpoints. |

### Steam account/API permission and security gate

Valve's [Web API Terms](https://steamcommunity.com/dev/apiterms) permit use only in accordance with API documentation and require, among other things, retrieving data about a user only at that user's request, a privacy policy covering non-public Steam data and its storage countries, keeping the Web API key confidential, no collection/storage of Steam passwords, and no implication that the app is Valve/Steam-endorsed. Steam's [key-authentication guide](https://partner.steamgames.com/doc/webapi_overview/auth?language=english) says user keys require a Steam account, associated domain name, and agreement to the terms; it warns publisher keys are sensitive and intended for secure backend use. Never ship an app key in the open-source client. A local-only desktop design still needs to respect key confidentiality; do not ask the user to paste their Steam password.

Steam profile visibility is not equivalent to API permission for all fields. For example, Steam's [Private Games guidance](https://help.steampowered.com/en/faqs/view/1150-C06F-4D62-4966) says marking a game private hides its ownership, playtime, and activity from other users. Respect whatever the API returns; do not probe around privacy. Steam Web API terms expressly allow distribution of Steam Data to end users for their personal use via the registered application, but this does not make Valve's logos, store capsule art, or other third-party artwork generally reusable. Record the source/ID and show Steam branding only in line with Valve's current rules; persist remote cover art only after confirming a license for that exact use.

**Recommendation:** first provide Steam library import only behind a visible opt-in and compliant key/privacy design; let the user choose whether to include played free games. Clearly label imported games as “in Steam library” with optional playtime, never “completed.” Exclude Wishlist and store Cart for now. A user-supplied export/manual CSV path can be considered separately if the user obtains data through Steam's own UI; do not claim Steam officially exports these lists until an official export workflow and schema are verified.

## Matching imported rows to catalog metadata

Provider IDs are stronger than titles, but they are namespaced: persist `(provider, provider_entity_type, external_id)` and a separate mapping to Tastellar's local work. Keep edition, season, adaptation, and game AppID distinctions. Metadata search is a separate feature from importing a user's list: importing user activity does not grant permission to query or retain a provider's catalog or covers.

| Import source / category | Best initial identity or lookup | Proposed user flow |
|---|---|---|
| IMDb ratings / check-ins / watchlist — film and TV | Native IMDb `tt…` ID. A header-only/sample fixture validated fields `OriginalTitle`, localized `Title`, `Year`, and `ReleaseDate` (which can differ), plus the IMDb ID. TMDB offers a [`/find`](https://developer.themoviedb.org/reference/find-by-id) endpoint for known IDs and supports IMDb ID as an external source, subject to its terms gate. | Query TMDB by the user-exported IMDb ID; compare source title/type/year and make the user confirm ambiguous or conflicting results. The sampled file had no cover. Do not scrape IMDb pages or copy IMDb datasets. TMDB's API eligibility is blocked until its commercial/donation classification is resolved in writing. |
| Letterboxd export — films | Native export identity is the Letterboxd URI, not an IMDb/TMDB ID. One inspected native export had `Name`, `Year`, `Letterboxd URI` (with file-specific activity/rating columns); its native rows lacked cross-provider IDs and covers. The separate Letterboxd *import* template accepting `imdbID`/`tmdbID` does not prove its *export* contains them. | Match title + year to TMDB search candidates only if/when TMDB is enabled, and show candidates for user confirmation. Preserve Letterboxd URI as its own external ID. Never fetch hidden IDs or scrape a Letterboxd page to create a crosswalk. |
| MAL list/manual titles — anime/manga | Prefer a verified user-provided MAL ID if present. Otherwise use title + native format (anime/manga) + year/creator as candidate signals. MAL's API must be checked separately against current docs/terms; HTML acquisition is not implicitly authorized merely because a list is public. | Accept a manual title list or verified export, then offer independent catalog candidates; do not silently transform a scraped MAL page into an import source. TMDB anime series coverage is not a complete MAL crosswalk; no automatic MAL-ID→TMDB-ID assumption. |
| Goodreads CSV — books / literature | One inspected test export has Goodreads `Book Id`, `ISBN`, `ISBN13`, publication year, author, publisher, binding, and pages; ISBN fields were present for 6 of 8 rows, and no cover field was present. Goodreads Book ID is provider-local; it is not an Open Library ID. | ISBN exact lookup first through [Google Books](https://developers.google.com/books/docs/v1/using) or [Open Library Search](https://openlibrary.org/dev/docs/api/search). If ISBN is absent, query title + author + publication year and ask the user to choose the edition/work. Do not infer ISBN or edition from title alone. Keep work identity and edition identity separate. These are header/field observations for one test file, not a promise of universal headers. |
| Steam `appid` — games | Preserve the exact Steam AppID; Steam's [`IStoreService/GetAppList`](https://partner.steamgames.com/doc/webapi/IStoreService?l=english) is a documented catalog listing endpoint, not a cover-rights grant or an end-user wishlist/cart API. IGDB is another candidate catalog but has separate Twitch credentials and terms. | Match Steam-owned rows directly by AppID, then enrich with name/release date/type only if the selected source terms allow the planned use. A Steam AppID should not be replaced with an IGDB ID; save both provider identities if a confirmed crosswalk is found. |

### Catalog search and artwork gates

- **TMDB (film/TV):** its [FAQ](https://developer.themoviedb.org/docs/faq) says free use is for non-commercial projects with attribution and requires a notice; it describes commercial use in revenue-benefit terms. Donations/subscriptions on Boosty are an unresolved classification, not an automatic exemption or automatic violation. Keep search disabled until TMDB gives written permission/classification or the project obtains a suitable license. Even authorized API access does not itself settle copyright in every poster image.
- **IGDB (games):** [official API docs](https://api-docs.igdb.com/) describe a free non-commercial API, commercial partnership route, server-side credential requirements, and local caching guidance. Obtain written classification if the app accepts financial contributions. Returned cover paths do not by themselves license unrestricted republication or bundling of cover art.
- **Google Books (books):** [Volume API docs](https://developers.google.com/books/docs/v1/using) support title/author/ISBN search and expose edition metadata/thumbnail links. Follow its API terms, branding, attribution, and image/content restrictions; do not assume thumbnail URLs grant offline storage or redistribution rights.
- **Open Library (books/editions):** [Search API](https://openlibrary.org/dev/docs/api/search) helps distinguish works and editions. [Covers API guidance](https://openlibrary.org/dev/docs/api/covers) recommends linking/hotlinking from public pages and says not to crawl or bulk-download. The cited guidance does not clearly grant broad offline cache/backup rights; treat those as unknown and use remote previews only until clarified. A cover URL does not transfer the image copyright.
- **Comics:** Google Books/Open Library can help identify book-format graphic novels, but they are not complete serial comics catalogs. Comic Vine's [API terms](https://comicvine.gamespot.com/api/) include non-commercial/no-redistribution conditions; do not make it the default while Boosty status is unresolved. Search for a licensed source or leave comics manual-first.
- **No scraping fallback:** search must use documented APIs with allowed query/display behavior, or user-provided data. Do not crawl search engines or provider pages for catalog rows or covers. If image rights/cache limits are unclear, show a preview only when the provider terms allow it, save no remote image, and keep manual cover upload available.

## Confidence and open verification

- **High confidence:** Steam endpoint purposes/visibility/free-game behavior, privacy/key requirements, ItemCart's developer checkout role, and the distinct developer-facing scope stated by Valve's Wishlist Data API announcement; all are first-party sources linked above.
- **Not verified:** whether Valve exposes a separate documented API for a user's own wishlist or store cart; exact DLC entitlement behavior from `GetOwnedGames`; the current fields returned for this particular profile; whether Steam API results include a durable cover URL; and whether a particular game offers useful public achievement data. Do not implement based on assumptions in these areas.
- **High confidence but conditional on re-check:** TMDB/IGDB non-commercial gates, Open Library's no-crawl/no-bulk-download direction, Google Books API search capability, and source-specific image-use limits. Revisit exact current provider terms before implementation, particularly the Boosty contribution arrangement and persistent artwork use.
- **No request was made to Steam.** A public-looking profile link or a user statement about their account does not substitute for API key/auth setup, endpoint response, privacy visibility, user consent, or permission to use undocumented endpoints.
